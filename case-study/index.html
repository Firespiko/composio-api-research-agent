02 · The agent

Automate the repetitive work. Keep judgment explicit.

Retrieval, extraction, verification and analysis are separate stages. Each research result is checkpointed, so an API/search failure does not force a complete restart.

01 · INPUT

100 apps

Load app names, categories and research hints.

03 · EXTRACT

Gemma

Local model produces validated structured fields.

04 · CHECKPOINT

JSON state

Persist research results incrementally for resumability.

05 · VERIFY

Independent pass

Separate retrieval + model comparison finds disagreements.

06 · ANALYZE

Case study

Aggregate results and expose the complete research matrix.

What the agent does

  • Searches for developer/API/authentication evidence.
  • Ranks and deduplicates retrieved evidence.
  • Extracts auth, access, API, SDK, MCP and buildability fields.
  • Validates the output against a strict schema.
  • Runs independent verification and records corrections.

Where a human is still needed

  • Define the research schema and what counts as evidence.
  • Set verification policy and confidence thresholds.
  • Review disputed/ambiguous records and source quality.
  • Interpret aggregate patterns and decide what merits follow-up.
  • Audit failures instead of silently converting missing evidence into facts.
Important implementation note: this current artifact uses Tavily for retrieval and a local Gemma model for extraction. It does not claim a Composio SDK/MCP integration that is not actually implemented in the submitted code.

06 · Method & honesty

What the system proves — and what it does not.

98 / 100 coverage

98 applications produced research records. Two target applications were not successfully researched in the current run.

Verification is a quality signal

The 33-record verification set is not random. Its correction rate demonstrates that the second stage can expose disagreements; it is not a measured error rate for the whole dataset.

Evidence quality varies

The retriever prefers developer/API-looking sources, but that heuristic is not proof of official ownership. Production use should audit source quality and timestamps.

Confidence is triage

Model confidence is used to decide where to spend verification effort. It is not calibrated probability of correctness.

Documentation changes

API docs, pricing and credential requirements change. Evidence URLs should be retained and rechecked when this becomes a production workflow.

Failure handling

Search failures are isolated per app/query and successful records are checkpointed. Completeness is therefore visible rather than hidden.
